// Open the Status page and connect
User > Web Client: Open Status
Web Client > WebSocket API: Connect with JWT
WebSocket API > WS Handlers: Invoke $connect
WS Handlers > WS Handlers: Verify JWT against public keys

alt [label: token valid] {
  WS Handlers > DocBeam DB: Insert row in ws_connections with the token expiry
}
else [label: token invalid] {
  WS Handlers --> Web Client: 401, no connection
}

// One list of everything the user can see (read on open, after a send, cancel or retry, and every 30 s while something runs; no pushes for the list)
Web Client > API Gateway: GET /jobs?scope=all (+ status, sender, sentSince, team filters from the address; limit 20)
API Gateway > DocBeam API: Validate JWT and forward
DocBeam API > Document Platform: Which teams is this user in? (cached 60 s)
Document Platform > Platform DB: Read the user's teams
Document Platform --> DocBeam API: Team IDs
DocBeam API > DocBeam DB: Read jobs (the user's, and others' with a delivery to the user's teams), newest first (created_at, id), with task counts, file names and folders, one query per page
DocBeam API --> Web Client: Rows and nextCursor (others' jobs show only what reached the user's teams)
Web Client > API Gateway: GET /jobs/running (the number on the Status tab, ignoring filters)
API Gateway > DocBeam API: Validate JWT and forward
DocBeam API --> Web Client: How many visible jobs still have a pending or in-progress delivery

loop [label: the end of the list scrolls into view and nextCursor is set, icon: repeat] {
  Web Client > API Gateway: GET /jobs with ?cursor= (same filters)
  API Gateway > DocBeam API: Validate JWT and forward
  DocBeam API --> Web Client: Next 20 rows (merged by id; nothing repeated or skipped)
}

opt [label: Open by ID with the 8-character ID from the list] {
  Web Client > API Gateway: GET /jobs?idPrefix= (a full ID or a link opens directly)
  API Gateway > DocBeam API: Validate JWT and forward
  DocBeam API > DocBeam DB: Range on the primary key, among the jobs the user can see (at most 5)
  DocBeam API --> Web Client: Matches (one opens; several to choose from; none: 'No distribution with that ID that you can see')
}

// Pick a job (row click, copied link or Open by ID) and subscribe before fetching
User > Web Client: Open a job in the side panel
Web Client > WebSocket API: Subscribe with jobId
WebSocket API > WS Handlers: Invoke subscribe
WS Handlers > DocBeam DB: Look up the job's sender

opt [label: caller is not the sender] {
  opt [label: no cached service token] {
    WS Handlers > Auth Service: Request service token
    Auth Service > Auth DB: Verify client secret hash
    Auth Service --> WS Handlers: Service JWT
  }
  WS Handlers > Document Platform: Which teams is the caller in?
  Document Platform > Platform DB: Read the caller's teams
  Document Platform --> WS Handlers: Team IDs
  WS Handlers > DocBeam DB: Does the job have a delivery to one of those teams?
}

alt [label: sender, or job has a delivery to the caller's team] {
  WS Handlers > DocBeam DB: Set job_id and team_ids on the connection row
  WS Handlers --> Web Client: subscribed
}
else [label: not allowed, or no such job] {
  WS Handlers > DocBeam DB: Clear any earlier job on the connection row
  WS Handlers --> Web Client: subscribe_error NOT_FOUND (same answer for both)
}

// Fetch the tasks only after the subscribed answer (no answer in 5 s: fetch anyway)
Web Client > API Gateway: Request job tasks with JWT
API Gateway > DocBeam API: Validate JWT and forward
DocBeam API > DocBeam DB: Look up the job's sender

opt [label: caller is not the sender] {
  DocBeam API > Document Platform: Which teams is the caller in? (cached 60 s)
  Document Platform --> DocBeam API: Team IDs
}

alt [label: sender] {
  DocBeam API > DocBeam DB: Read all tasks (100 per page, with the detected file type and attempts)
  DocBeam API --> Web Client: Every delivery in the job
}
else [label: job has a delivery to the caller's team] {
  DocBeam API > DocBeam DB: Read tasks for the caller's teams only (100 per page)
  DocBeam API --> Web Client: Only the deliveries to the caller's teams ('Showing deliveries to your teams: ...')
}
else [label: no delivery to the caller's teams] {
  DocBeam API --> Web Client: 404 Not found
}

// Live updates
opt [label: a delivery starts its second or a later try] {
  Delivery Lambda > DocBeam DB: Claim the task (attempt + 1), find subscribers (same rule)
  Delivery Lambda > WebSocket API: PostToConnection (task_update, in_progress, attemptCount)
  WebSocket API --> Web Client: The row shows 'Retrying'; its attempts are in the tooltip
}

loop [label: each final task status from Delivery Lambda, icon: repeat] {
  Delivery Lambda > DocBeam DB: Update task status (job row locked)
  Delivery Lambda > DocBeam DB: Find subscribers: the sender, and viewers whose team_ids include the task's team, token not expired
  Delivery Lambda > WebSocket API: PostToConnection (status, updatedAt, counts for what each viewer can see; cancelled counted apart from failed)
  WebSocket API --> Web Client: Live update (older than the row already shows: ignored)
  opt [label: connection gone (410)] {
    Delivery Lambda > DocBeam DB: Delete connection row
  }
}

opt [label: task fails after 5 attempts or fan-out fails] {
  DLQ Consumer > DocBeam DB: Mark task failed with reason
  DLQ Consumer > DocBeam DB: Find subscribers (same rule)
  DLQ Consumer > WebSocket API: PostToConnection
  WebSocket API --> Web Client: Live update
}

opt [label: connection drops or token renewed (every 15 min, with the refresh cookie)] {
  Web Client > WebSocket API: Reconnect with JWT, subscribe with jobId (checked again)
  WebSocket API --> Web Client: subscribed
  Web Client > API Gateway: Refetch job tasks
}

opt [label: user leaves the page] {
  WebSocket API > WS Handlers: Invoke $disconnect
  WS Handlers > DocBeam DB: Delete connection row
}

// The web app shows job history only: audit events are still written, and GET /audit still answers, but no screen calls it (D-F1-13)

// Retry from the job panel
opt [label: sender presses Retry failed] {
  Web Client > API Gateway: POST /jobs/:jobId/retry with JWT
  API Gateway > DocBeam API: Validate JWT and forward
  DocBeam API > DocBeam DB: Sender only (403 NOT_SENDER otherwise); lock job row, reset retryable failed tasks to pending, audit event
  DocBeam API --> Web Client: 202, tasks show as waiting again (409 JOB_CANCELLED for a cancelled job)
  DocBeam API > WebSocket API: PostToConnection (job_update to the job's open dashboards)
  WebSocket API --> Web Client: Other tabs and team viewers reload the tasks
}

// Cancel from the job panel
opt [label: sender presses Cancel distribution (offered only while it runs) and confirms] {
  Web Client > API Gateway: POST /jobs/:jobId/cancel with JWT
  API Gateway > DocBeam API: Validate JWT and forward
  DocBeam API > DocBeam DB: Sender only (403 NOT_SENDER otherwise); lock job row, set cancelled_at, mark pending tasks failed (CANCELLED), close job if nothing is running, audit event
  DocBeam API > DocBeam DB: Find the job's open dashboards
  DocBeam API > WebSocket API: PostToConnection (job_update, counts for what each viewer can see)
  WebSocket API --> Web Client: Reload the tasks; waiting deliveries show Cancelled (grey, counted apart from failures), running ones finish
}

// Daily clean-up
opt [label: once a day] {
  Sweeper > DocBeam DB: Delete ws_connections rows past their expiry (browsers that vanished without $disconnect)
}
