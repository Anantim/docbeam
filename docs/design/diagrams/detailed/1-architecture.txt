// Client and edge
CloudFront > Web Client: serve SPA
Web Client > CloudFront: API calls on /api/* (15-min JWT, renewed 1 min before expiry with the refresh cookie on /api/auth)
CloudFront > API Gateway: forwards /api/*, prefix stripped (one site for the cookie)
Web Client <> WebSocket API: live status
Web Client --> Object Store: presigned POST/GET (file bytes)

// Edge into the private network
API Gateway > Internal ALB: VPC Link (explicit routes, no catch-all)
API Gateway --> Auth Service: signing keys (OpenID configuration, read when the authorizer is created; JWKS)
Internal ALB > Auth Service: listener :3001, HTTP inside the VPC
Internal ALB > DocBeam API: listener :3003
Internal ALB > Document Platform: listener :3002

// Each service owns its database (direct, no proxy)
Auth Service > Auth DB: users (with sign-in pause), refresh tokens, service clients
DocBeam API > DocBeam DB: files, jobs, tasks, audit_events
Document Platform > Platform DB: teams, members, binders, folders, documents
Document Platform > Platform File Store: delivered documents

// Uploads larger than 100 MB
DocBeam API > Object Store: start and complete multipart upload (part SHA-256s, files > 100 MB)

// Confirm and scan each upload (ADR-016)
Object Store > Upload Events Queue: new object in staging/
Upload Events Queue > Upload Events Lambda: trigger
Upload Events Queue --> Upload DLQ: after 5 failed attempts
Upload Events Lambda > Object Store: check size and SHA-256, scan with ClamAV, tag clean, or delete a file that does not match or is infected

// Service-to-service calls
DocBeam API > Document Platform: destination check, user's teams
DocBeam API > Auth Service: service token

// Submission and fan-out
DocBeam API > Job Queue: submit job
DocBeam API > WebSocket API: push job update after a cancel
Job Queue > Fan-out Lambda: trigger
Job Queue --> Job DLQ: after 3 failed attempts
Fan-out Lambda > Task Queue: batch send
Task Queue --> Task DLQ: after 5 failed attempts (30 s, 2, 5, 10 min apart)
Task Queue > Delivery Lambda: trigger (max 50 at a time)

// Delivery
Delivery Lambda > Object Store: HEAD checksum, stream file
Delivery Lambda > Auth Service: service token
Delivery Lambda > Document Platform: deliver (platform checks member, type, SHA-256; takes 6 at once, 503 when busy)
Delivery Lambda > WebSocket API: push update (sender and that team's viewers)

// Failure handling
Job DLQ > DLQ Consumer: trigger
Task DLQ > DLQ Consumer: trigger
Upload DLQ > DLQ Consumer: trigger
DLQ Consumer > WebSocket API: push update (sender and that team's viewers)

// Lost-message recovery (ADR-014)
Scheduler > Sweeper Lambda: every minute (re-send), daily (cleanup)
Sweeper Lambda > Job Queue: re-send jobs not fanned out 2 min after queued
Sweeper Lambda > Object Store: delete files not submitted within 24 h (daily)

// Live status connections
WebSocket API > WS Handlers: invoke on connect / subscribe / disconnect
WS Handlers > Auth Service: service token, JWKS
WS Handlers > Document Platform: user's teams (visibility)

// All Lambda database access goes through RDS Proxy in prod (in dev, straight to the instance, one connection each)
Fan-out Lambda > RDS Proxy: read tasks, set fanned_out_at
Delivery Lambda > RDS Proxy: lock job, update task, audit event, complete job, find subscribers
DLQ Consumer > RDS Proxy: mark tasks or files failed, audit event, find live subscribers
Upload Events Lambda > RDS Proxy: set uploaded_at and scan_status, audit event
WS Handlers > RDS Proxy: ws_connections (token expiry, viewer's teams)
Sweeper Lambda > RDS Proxy: find stuck jobs, unclaimed files
RDS Proxy > DocBeam DB: pooled connections

// Alerting
Job DLQ --> Alarms: depth > 0 for 5 min
Task DLQ --> Alarms: depth > 0 for 5 min
Upload DLQ --> Alarms: depth > 0 for 5 min
Delivery Lambda --> Alarms: error rate
