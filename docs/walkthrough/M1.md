# M1 walkthrough: Browse destinations

## 1. The big picture

M1 lets a person register, sign in and see only the teams, binders and folders they belong to. It adds three things: the Auth Service (who you are), the Document Platform's folder tree and its membership rules (what you may see), and the public edge (API Gateway in front of a private network) with the first screens of the web app. The DocBeam API exists only as an empty service with its full database, ready for M2. Everything later (upload, send, track, download) builds on one rule proven here: **every answer is filtered by team membership, and anything you may not see looks like it does not exist**.

## 2. One request, start to finish

Priya opens the app, signs in and expands the Cardio team.

**Step 1. The browser asks for the page.** CloudFront serves the React app from an S3 bucket. A small CloudFront Function answers any path without a dot with `index.html`, so a deep link still opens the app.
- Why: one site for the page and the API, so the refresh cookie can be `SameSite=Strict` without a domain (D-G5).
- Code: `infra/modules/cloudfront/main.tf` (functions `spa` and `api_strip`), `web/src/main.tsx`.
- AWS: CloudFront, the distribution, Origins and Behaviors.

**Step 2. She signs in.** The page posts the email and password to `/api/auth/login`. CloudFront's second behaviour (`/api/*`, no caching) strips `/api` and forwards to API Gateway, which has no token check on this route. It forwards through the VPC Link to the internal ALB, listener 3001, and the Auth Service.
- Why: login must be reachable without a token (ADR-001); it is throttled to 5 a second (D-G19).
- Code: `services/auth/src/routes/accounts.ts` (login), `infra/modules/api-gateway/main.tf`.
- AWS: API Gateway `docbeam-dev-api`, Routes and Stages; EC2, Load balancers `docbeam-dev-internal`, Listeners.

**Step 3. The Auth Service checks the password.** It reads the user, compares the bcrypt hash (against a dummy hash if the email is unknown, so timing gives nothing away), then updates the wrong-password count in a short transaction. Five wrong passwords in a row pause the account for 15 minutes with the same 401.
- Why: same message and timing for every failure (ADR-015, D-M1-7).
- Code: `login-attempts.ts` (the counting), `passwords.ts`, `routes/accounts.ts`.
- Test: `login-attempts.test.ts`, `tests/integration/auth.test.ts`.

**Step 4. Two tokens come back.** A 15-minute access token (RS256, `kid`, `iss`, `aud`, `token_use: user`, her name) in the body, and a refresh token in an HttpOnly cookie for `/api/auth`. Only the SHA-256 of the refresh token is stored.
- Why: a stolen access token lives 15 minutes; script code on the page cannot read the cookie (ADR-015).
- Code: `keys.ts`, `tokens.ts`, `sessions.ts`. The key is in Secrets Manager (`docbeam-dev/auth/signing-key`), written once by `bootstrap-signing-key.ts`.
- AWS: Secrets Manager; RDS `auth_db` table `refresh_tokens` (hash only).

**Step 5. She expands Cardio.** The page calls `GET /api/teams/<id>/binders` with the access token. API Gateway's JWT authorizer fetches the keys through `/.well-known/openid-configuration`, checks signature, `iss`, `aud` and expiry. A missing or bad token ends here with 401 and never reaches the ALB.
- Why: unauthenticated traffic must not enter the network (ADR-001).
- Code: `infra/modules/api-gateway/main.tf`, `infra/envs/dev/services.tf` (`public_routes`).
- AWS: API Gateway, Authorizers; CloudWatch Logs `/docbeam/docbeam-dev/api-gateway` (the 401s).

**Step 6. The platform answers from one query.** The Platform checks the token again (`token_use: user`), then runs a query that starts from her `team_members` row. No row means no result and a 404.
- Why: permission is part of the data access, never a check someone can forget (flow 1, "Who can see what").
- Code: `services/platform/src/routes/browse.ts`.
- Test: `tests/integration/platform.test.ts`.
- AWS: ECS, `docbeam-dev-platform`; RDS `platform_db`.

**Step 7. A minute before the 15 minutes end**, the page takes a browser lock, swaps the refresh cookie for a new pair and tells other tabs. If the same refresh token ever comes back twice, the whole sign-in is cancelled.
- Code: `web/src/auth/session.ts`; `services/auth/src/sessions.ts`.
- Test: `session.test.ts` (web), `sessions.test.ts` and `auth.test.ts` (service).

## 3. The parts that matter most

**A. Membership inside every browse query.**
- *What could go wrong:* a route forgets the check and shows another team's binder, or answers 403 so its existence leaks.
- *How it is prevented:* each route is one SQL statement joined to `team_members` for the caller. A stranger and a missing id get the same 404. A malformed id gets the same 404.
- *Proof:* `platform.test.ts` ("lists a member's binders and answers 404 for another team", "reads one level of a binder…", "answers 404 for an id that is not a UUID").

**B. The sign-in and its tokens.**
- *What could go wrong:* a user token used as a service token, a replayed refresh token, a guessable error message, passwords or tokens in a log.
- *How it is prevented:* every token carries `token_use`, and the shared verifier refuses the wrong kind. Refresh tokens work once and a reused one ends the family. Only hashes are stored. The login answer is one message.
- *Proof:* `tokens.test.ts`, `sessions.test.ts`, `auth.test.ts` ("a used token coming back cancels the whole sign-in", "gives the same 401…").

**C. The edge lists routes one by one.**
- *What could go wrong:* `/auth/token` (mint service tokens) or `/internal/users` reachable from the internet.
- *How it is prevented:* API Gateway has 10 routes and no catch-all. The internal routes are not among them, so they answer 404 at the gateway.
- *Proof:* checks 3 and 12 in `docs/testing/M1-RESULTS.md` (404 on dev; the route list). Terraform: `public_routes` in `services.tf`.

**D. Repeat-safe ingest.**
- *What could go wrong:* the same delivery arriving twice stores two documents, or a renamed program is accepted as a PDF.
- *How it is prevented:* a unique `source_task_id` with `ON CONFLICT DO NOTHING`; the loser deletes its object. The first bytes are checked against the declared type and the SHA-256 is recomputed while streaming.
- *Proof:* `tests/integration/ingest.test.ts` (parallel repeats, 422 UNSUPPORTED_TYPE, 422 CHECKSUM_MISMATCH).

## 4. What can safely be ignored for now

- The Terraform plumbing in `ecs-service` and `alb` (security groups, roles, log groups) once it applies cleanly.
- `web/src/styles.css` and the layout components.
- The seed generator `seed/generate.mjs` (it only writes the two JSON files).
- The DocBeam API: it only serves `/health` until M2.

## 5. Questions a reviewer might ask

1. **Why can a user not tell a missing binder from one in another team?** Both are 404 from the same query. `services/platform/src/routes/browse.ts`.
2. **What stops an internal route being called from the internet?** It is not in the gateway's route list. `infra/envs/dev/services.tf`, `public_routes`.
3. **Where is the signing key and who can read it?** Secrets Manager `…/auth/signing-key`; only the auth task's execution role can inject it, and only the one-off signing-key task can write it. `infra/modules/ecs-service/main.tf`, `envs/dev/services.tf`.
4. **What happens to a stolen refresh token?** The first time both copies are used, the family is revoked and both are signed out. `services/auth/src/sessions.ts`.
5. **Why is the cookie `Path=/api/auth`?** Because the browser sees the API under `/api` on the CloudFront address. D-G5.
6. **Why does the first apply need two steps?** API Gateway reads the issuer's OpenID configuration when it creates the authorizer. D-M1-13, `jwt_authorizer_enabled`.
7. **What does a 21st destination do?** Nothing is added and a toast explains. `web/src/destinations/selection.ts`.
8. **How does the seed avoid deleting data?** It adds and renames, and removes only memberships. A lookup error stops it rather than pruning. `services/platform/src/seed.ts`, `seed-run.ts`.
9. **Why is the auth task bigger than the others?** bcrypt cost 12 is CPU-bound. D-M1-13.
10. **Is traffic inside the network encrypted?** No: plain HTTP behind security groups, an accepted risk. D-M1-2.

## 6. Words used

- **Access token**: the 15-minute signed pass sent with every request.
- **ALB**: the internal load balancer in front of the three services.
- **Authorizer**: the API Gateway check of a token's signature, issuer, audience and expiry.
- **bcrypt**: a deliberately slow password hash.
- **Binder / folder**: the two levels of the tree below a team.
- **Family**: all refresh tokens of one sign-in.
- **JWKS**: the public keys that check token signatures.
- **Migrate task**: a one-off ECS task that runs a service's database migrations.
- **One-off task**: an ECS task that runs once and exits (bootstrap, migrate, seed, signing key).
- **Refresh token**: the long-lived, single-use token in the cookie.
- **Seed**: the script that loads teams, binders, folders and memberships.
- **Service token**: a token for one internal caller, with scopes.
- **VPC Link**: how API Gateway reaches the private network.
- **Web Locks**: the browser feature that lets one tab at a time refresh.
